## 二、errno 8 的排查过程（三个变体全部被拒）

| 变体 | 加载命令 | 结果 |
|---|---|---|
静态 arm64 | `LC_UNIXTHREAD` pc=0x100000338，无 dyld | errno 8 |
动态 arm64 | `LC_LOAD_DYLINKER` + `LC_LOAD_DYLIB` + `LC_MAIN` | errno 8 |
arm64e | cpusubtype `0x81000002` | errno 8 |

三种都带 `LC_CODE_SIGNATURE`（ad-hoc 签名）。

**文件本身已用挂载验证，不可能是文件问题：**

```
fsapfsmount seed → /sbin/launchd  34,848 B  mode 755
首 16 字节: cf fa ed fe 0c 00 00 01 00 00 00 00 02 00 00 00
            MH_MAGIC_64  arm64        MH_EXECUTE
```

同时也排除了：

- 内核读不到文件（路径解析正常：先试 `.development` 再试 `launchd`）
- APFS 未挂载（`BSD root: md0` 已确认）
- 缺入口（`LC_UNIXTHREAD` pc 落在 `__TEXT` 内）
- 缺 dyld（动态变体同样被拒，说明根本没走到 dyld）

**结论：XNU 在 Mach-O 激活阶段按平台策略拒绝，剩余门槛是可信签名/平台二进制属性，
36 MB 的自制载荷通道无法满足。**

`execfailurereports=1`、`cs_debug=1` 这两个引导参数在本内核上没有产生额外输出，
说明该构建未编译相应报告路径，无法靠引导参数获得更细的拒绝原因。

## 三、外部存储（独立供电 hub）的实测结论

`ExtStorageProbeDxe` 的两轮测量把问题缩到一个点：

```
capdir=1                        dwc3 已在主机模式
PORTSC1 000206E1 -> 复位 -> 00220603  端口能被复位到 U0 running (PED=1)
USBCMD=00000000  RS=0
USBSTS=00000011  HCH=1         控制器处于 halted
CRCR=00000000                  命令环地址为空
```

即：**PHY 与链路正常，端口能起来，但没有驱动把 xHCI 启动起来**，因此不会发出
SET_ADDRESS / GET_DESCRIPTOR，永远不会枚举出块设备（U 盘灯不亮）。

下一步（可直接实施）：

```
1. 控制器软复位：USBCMD.HCRST，等 HCRST 自清
2. 写 DCBAAP（设备上下文数组指针）
3. 写 CRCR（命令环）并挂 ERST（事件环段表）
4. USBCMD.RS=1 + INTE=1，等 USBSTS.HCH 清零
5. 之后交给 XhciDxe / UsbBusDxe / UsbMassStorageDxe
```

寄存器基线（已实测）：dwc3 `0x0A600000`，XHCI 操作区偏移为 CAPLEN（本机 0x20），
端口寄存器从 `base + caplen + 0x400` 开始。
