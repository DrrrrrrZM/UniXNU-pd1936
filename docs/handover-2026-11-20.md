## 三、当前唯一未完成的一步

CI 第 9 步失败：

```
hdiutil: create: -format requires -srcfolder or -srcdevice
```

修法（改 .github/workflows/kernel.yml 的 "build an APFS seed" 步骤）：

```yaml
mkdir -p /tmp/root/sbin
cp /tmp/launchd /tmp/root/sbin/launchd
chmod 755 /tmp/root/sbin/launchd
hdiutil create -size 128m -fs APFS -volname PD1936ROOT \
    -srcfolder /tmp/root -format UDRW /tmp/seed
cp /tmp/seed.dmg device/seed-root.img
```

要点：`-srcfolder` 负责把内容放进卷里，`-format UDRW` 产出裸磁盘映像。
第 8 步（预编译二进制 `src/launchd-aarch64`）已经通过，不需要再动。

## 四、构建成功后的打包流程（本地）

```bash
# 1) 取 CI 产物
python pack_from_ci.py --run-id <ID> --out boot-raw.img

# 2) 给新内核重打两个补丁
python skip_probe.py kernel-ci.macho k1.macho          # 控制台：跳过 0x3C0FC000 探测
python apfs_literal.py k1.macho k2.macho               # Apple_HFS -> Apple_APFS 字面量

# 3) 验证种子非全零、ADT 含 RAMDisk
python fat_tool.py list payload.img
strings -a payload.img | grep -c PD1936ROOT

# 4) 写回 + 压缩 + 打镜像
python fat_tool.py put payload.img EFI/UNIXNU/PAYLOADS/KERNEL~1.MAC k2.macho
lz4 -l -9 payload.img payload.lz4
python make_payload_boot.py --payload payload.lz4 --out boot-final.img --allow-oversize
```

## 五、失败时的判读

| 日志 | 含义 | 处理 |
|---|---|---|
出现 `PD1936: process 1 is running` | 用户态已跑起来 | 里程碑达成，转而补根卷内容 |
仍 `exec /sbin/launchd failed errno 8` | 卷内文件不可执行 | 检查 codesign / Mach-O 是否被正确写入 |
errno 2 | 卷内没有该文件 | 检查 hdiutil 是否真的写入了 /sbin/launchd |
仍 `Waiting on ... Apple_APFS` | rd=md0 没生效或卷未被认 | 回到 IOFindBSDRoot 的路由分析 |
